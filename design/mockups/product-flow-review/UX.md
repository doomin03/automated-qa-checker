# QA Studio 화면 기획

## 제품 목표와 역할

팀에서 검토한 공용 시나리오를 찾아 자기 프로젝트에 맞게 수정하고, 검증한 문서를 명시적으로 실행한 뒤 근거를 검토한다. 웹은 **사용자용 공용 시나리오·XML 전달·실행 진행 앱**이다. Flutter Desktop은 **블록/Flow 또는 XML로 테스트를 작성·수정·검증·실행하는 앱**이다. 독립 QA Engine은 실행 스키마/인터프리터/어댑터/CLI를 소유하며 Checker/중앙 서버 없이도 package API나 CLI로 사용할 수 있어야 한다.

관리 업무는 별도 제품이 아닌 동일 서버 API 위의 권한별 화면이다. 원본 MD의 관리자 웹 표현보다 최신 사용자 역할 정의를 적용했다. 실제 Flutter 구현은 기능별 MVVM과 Provider, Service/Repository, app composition root 경계를 따른다. 이번 HTML은 그 구조를 구현하는 제품 코드가 아니다.

| --- | --- | --- | --- | --- |

| 웹 실행 요청 | 공용 실행 검토 | 시나리오·버전·대상 확인 | 예시 요청 접수/배정 대기 | 실제 결과 없음, 연결 없음 |

| AI 변경 검토 | 문맥에 맞는 작성 보조 | CLI 진단, 전체/선택/앞/뒤, 요청 | 후보 전체 XML·변경 요약 | 오래된 후보, 취소, 적용 후 재검증 |
| 실행/증거 | 테스트 판정 확인 | 검증 후 실행, 진행 중 취소 | snapshot별 단계·이유·증거 | FAIL, 환경 오류, 취소, 후속 미실행 |
| 웹 결과 | 업무 후속 결정 | 단계·실패 원인·문서 버전 | 검토 대기와 테스트 판정 | 비교 조건 불일치 |

## 주요 여정

1. 웹에서 공용 시나리오 목적·사전조건과 게시 버전을 확인한다.
2. Desktop으로 받으면 출처 버전을 유지한 초안으로 열린다. 원래 게시 문서를 수정하지 않는다. 이미 편집한 문서가 있으면 유지/교체를 명시적으로 선택하고, 교체 시 재검증한다.
3. 프로젝트의 지침을 보면서 Blueprint 블록 또는 XML을 작성한다. XML과 node 그래프가 같은 원문 모델을 읽는다. 지원하지 않는 입력은 원문을 보존한다.
4. AI는 설치된 CLI의 인증을 사용하는 목표이며 앱에 키 입력 폼을 두지 않는다. 선택 문맥과 요청 범위를 확인하고 후보 XML의 전체 변경을 검토한다. 명시 적용/취소·되돌리기를 제공한다.
5. 문서 검증을 한 뒤 대상을 확인하고 테스트 실행을 누른다. 가벼운 목업 subset 검증과 실제 Engine 검증은 구별한다.
6. 실행 중 문서는 잠기고 결과는 실행 당시 revision에 속한다. 편집 후 이전 실행을 새 문서 결과처럼 덮어 그리지 않는다. 실행 결과는 웹에서 업무 검토 상태와 함께 보되 두 상태를 합치지 않는다.

## 상태와 전이

문서 상태는 검증 전 → 검증됨 → 수정 시 검증 전이다. 선택만 바뀌면 문서 검증을 유지하고 AI 후보만 오래된 후보가 된다. 검증 실패는 실행 전 오류이며 새 Run을 만들지 않는다. AI 제안·적용·undo·XML 전달도 runCount를 늘리지 않는다.

실행 요청과 테스트 결과를 분리한다. 웹 요청은 접수/배정 대기이고 결과가 없다. Desktop 실행 시연은 running에서 passed/failed/infra_error/cancelled 중 하나로 끝나며 취소 요청 중과 cancelled를 따로 보여준다. 정본의 blocked terminal 상태는 기획상 인지하되 이번 기본 시연 옵션에 추가하지 않았다. 후속 unrun은 단계/업무의 미실행 표시이며 별도 Engine terminal 판정을 발명한 것이 아니다. skipped는 step.finished의 결과이며 새 step.skipped 이벤트를 정의하지 않는다.

실행 mode는 시작 시 snapshot에 고정한다. 실행 중 설정 변경을 막고 취소 요청 뒤 유한 시간에 취소 완료로 바꾼다. 진행/환경 오류/취소에는 수집된 증거가 없음을 표시한다. PASS/FAIL 예시만 명시적 목업 증거를 볼 수 있다.

## 시각 디자인

차콜 배경과 단색 파랑 선택/주요 액션을 사용한다. 사용자 웹은 여백이 있는 목록·상세·결과 화면, Desktop은 도구형 도킹 구성이다. 그라데이션·장식 이미지·아이콘 남용을 피하고 한국어 제목/동작/상태를 우선한다. 기본 본문은 13~14px, 부수 메타데이터는 11~12px이며 얇은 경계와 명도 차로 패널을 나눈다. 상태는 색과 텍스트를 함께 표시한다.

1440×900에서 기본 로그인 7단계를 한 화면에 볼 수 있도록 노드 간격을 조정했다. 1024×768은 탐색을 접고 속성/AI/캔버스를 유지한다. 탐색을 펼치면 부차 도크를 접어 최소 중앙 400px을 보장한다. 패널 내부 스크롤로 좁은 화면에서도 조작을 유지한다. 노드 자유 배치·팬/줌·분기 편집은 이번 범위가 아니다.

Desktop AI change의 모든 제품 인수 task는 조사 시 미완료였다. 이번 목업 완료가 이를 완료로 바꾸지 않는다. 기존 서버는 alpha.6/0.3.0-draft.1, Desktop 계획은 alpha.8/0.3.0-draft.2이며 실제 호환 승격이나 pin 변경은 없다. 엔진 공개 alpha.6 fixture와 생성한 네 후보는 설치된 공개 CLI validate/plan으로 확인하며 실제 run은 호출하지 않는다.

## 후속 구현 우선순위

현재 Desktop AI 작업 공간 change에 따라 로컬 프로젝트/QA 저장, MVVM 도킹 View, CLI 작성·검증 승인, 실제 Windows·Engine 인수를 이어간다. 그다음 웹/서버 버전 전달과 실제 진행 수신, 서버 예약·역할/검수·Agent 상태를 연동한다. 기획 단계의 연결 상태나 fixture 성공을 실제 인증/외부 기기/제품 실행 성공으로 보고하지 않는다.
