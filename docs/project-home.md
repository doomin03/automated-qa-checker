# 프로젝트와 받은 QA 시작 화면

최신 앱은 `artifacts/releases/desktop-project-home-alpha8/Release/automated_qa_desktop.exe`다. 같은 Release 폴더의 DLL/data를 함께 유지한다. 이전 XML 블록 studio Release는 별도 경로에 보존했다. [목업](../design/mockups/xml-block-studio/index.html)은 같은 진입 흐름의 로컬 예시이며 서버/Engine 실행은 하지 않는다.

## 화면 흐름

| 화면 | 목적과 입력 | 행동과 결과 | 예외 |
| --- | --- | --- | --- |
| 내 프로젝트 | 이 컴퓨터의 프로젝트와 QA | 프로젝트 생성/선택 → QA 목록 → 작업실 열기 | 서버 없이 사용 가능; 검색 결과와 빈 프로젝트 구분 |
| 서버에서 받기 | 조직 로그인으로 접근 가능한 서버 프로젝트 | 게시 QA 버전/Suite 조회 → 고정 버전 확인 → 받을 로컬 프로젝트와 QA 이름 지정 | 연결/권한 오류는 기존 로컬 문서를 바꾸지 않음 |
| 가져온 QA | 이전에 받은 로컬 사본 | 프로젝트/원본 버전/수신 시각/로컬 변경 상태 확인 → 작업실 열기 | 서버가 없어도 저장된 XML과 원본 출처 사용 |
| 문서 작업실 | 선택한 로컬 QA의 XML | 명시 검증 → 실행 → 결과/PNG; XML 파일 블록 편집도 기존 경로로 제공 | 검증·수신은 자동 실행하지 않음 |
| 홈 복귀 | 현재 문서·블록 수정 상태 | 저장 후 이동 / 버리기 / 취소 | 실행·저장·조합·수신 중에는 문서 변경 제한 |

서버 연결은 홈에서 바로 연다. 조직 로그인을 우선 제공하며 로컬 테스트 토큰은 접힌 개발 연결 설정에서만 입력하고 메모리에 보관한다. 캐시 폴더는 앱 workspace 아래 자동 지정한다. 서버 프로젝트 목록은 `/me` membership을 따른다. `viewer`는 목록을 볼 수 있지만 pin/수신할 수 없다.

`받을 수 있는 QA`는 서버에 게시된 공용 버전이다. 현재 서버의 업무 담당자는 실행(run) 단위이므로 이 목록을 개인 배정 inbox라고 표시하지 않는다. Suite 버전을 고정한 뒤 해당 case를 개별 QA로 받는다. 전체 Suite 순차 실행 요청은 기존 사용자 웹/Agent 경로에 있다. 검색은 현재 불러온 페이지 범위이며 다음 페이지는 더 보기로 받는다.

## 사본과 원본

가져오기는 항상 새 로컬 QA를 만든다. 이미 받은 같은 버전은 `기존 사본 열기` 또는 `새 사본 받기`를 명시 선택하며 기존 초안을 덮어쓰지 않는다. 새 문서는 직접 XML 모드로 저장되며 조합 지원 범위 밖의 원문도 수신 단계에서 삭제하지 않는다. 파일 블록으로 사용할 때는 작업실의 명시 XML 가져오기를 사용한다.

workspace v1 JSON은 그대로다. 수신 출처와 원본 XML은 QA identity별 별도 immutable 파일에 보관한다. 서버 origin/project/version/XML hash/Suite 출처와 로컬 project/QA를 연결하며 토큰은 저장하지 않는다. 원본과 현재 문서의 XML bytes hash가 다르면 `로컬 수정됨`으로 표시한다. 저장이 중단되어 남은 출처 파일은 실제 로컬 QA가 없으면 목록에 노출하지 않는다. 손상 출처 파일을 자동 덮어쓰지 않고 원래 로컬 문서는 계속 열 수 있다.

## 실행과 공유의 범위

Desktop은 alpha.8, 기본 서버/Agent는 alpha.6을 유지한다. 기본 서버에서 받은 XML을 로컬 alpha.8에서 검증·실행할 수 있지만 alpha.8 결과를 기본 alpha.6 서버에 게시하는 것은 별개이며 runtime 불일치로 거부된다. 수신은 결과 자동 게시를 켜지 않는다. 동일 snapshot의 원본 version ID는 출처 연계이며 게시 호환 보증이 아니다. 수정/조합으로 snapshot이 달라지거나 다른 QA를 열면 이전 원본 version을 실행에 붙이지 않는다.

이번 실제 인수는 격리된 로컬 Nest/SQLite 서버와 Windows 앱을 사용했다. 운영 원격 서버, 실제 조직/Slack 계정, 개인 TC/Suite 배정 inbox를 새로 인수했다는 의미는 아니다. [검증 기록](validation-project-home.md)에서 실제 API·Engine 실행과 목업을 구분한다.
